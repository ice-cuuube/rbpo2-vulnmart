# Отчёт о расчёте надёжности программного обеспечения
## 1. Исходные данные
Для расчётов использовались следующие значения:
* число машинных команд программы I = 10 000;
* начальное число ошибок E0 = 50;
* исправлено ошибок = 30;
* время наработки t = 100 часов;
* коэффициент φ = 0,0001;
* коэффициент Ks = 0,0001;
* прогонов на подобласти Z1 = 100, отказов = 5;
* прогонов на подобласти Z2 = 50, отказов = 2;
* вероятности выбора подобластей P1 = 0,6 и P2 = 0,4;
* всего прогонов = 1000;
* безотказных прогонов = 970;
* отказов = 30;
* количество типов ошибок N1 = 20 и N2 = 10;
* вероятности типов ошибок a1 = 0,7 и a2 = 0,3.

## 2. Результаты расчётов
| Модель            |      R(100) |            MTTF |
| ----------------- | ----------: | --------------: |
| Джелински–Моранды |      0,8187 |       500 часов |
| Шуман             |     0,99998 | 5 000 000 часов |
| Нельсон–Коркорэн  | 0,954–0,986 |               — |
Дополнительно для модели Нельсона–Коркорэна была получена упрощённая оценка R = 0,97.

## 3. Интерпретация
Наиболее консервативную оценку даёт модель Джелински–Моранды.
Наиболее высокую оценку даёт модель Шумана.
Нельсон–Коркорэн находится между ними и использует результаты тестовых прогонов и распределение входных данных.
Значительное отличие оценок связано с различными предположениями моделей.

## 4. Графический анализ
Для моделей Джелински–Моранды и Шумана построен график зависимости вероятности безотказной работы от времени наработки.
Нельсон–Коркорэн на графике не представлена как функция времени, поскольку является статической моделью и рассчитывает надёжность по результатам тестовых прогонов.

## 5. Экспертная оценка
Для критических систем целесообразно учитывать консервативную оценку модели Джелински–Моранды.
При наличии статистики реальных тестовых прогонов полезно дополнительно применять модель Нельсона–Коркорэна.
Модель Шумана может быть полезна при наличии информации о размере программного продукта в машинных командах.

## 6. Интеграция
Модуль reliability_models.py был интегрирован в существующий Flask-проект VulnMart.
В приложение добавлен endpoint `/reliability`, через который можно получить JSON с рассчитанными значениями надёжности, интенсивности отказов и средней наработки до отказа.

## 7. Вывод
В ходе работы были изучены три классические модели надёжности ПО, выполнены ручные и программные расчёты, построен график зависимости надёжности от времени и выполнена интеграция математических моделей в существующее веб-приложение.
Полученные результаты показывают, что универсальной модели надёжности не существует. Для повышения достоверности оценки целесообразно использовать несколько моделей одновременно и учитывать специфику доступных данных.
